Add a prototype `VelcroDropdown` (alias `SlDropdown`), registered as `sl-dropdown` and built on the `@charm-ux/core` base element (core has no dropdown, and its menu component is a different model), with Shoelace 2.20.1's API: the `open`, `placement`, `disabled`, `stay-open-on-select` and `sync` properties (reflected; removing the attribute restores the initial value) and the non-reflected `containingElement`, `distance`, `skidding` and `hoist`, the `show()`, `hide()` and `reposition()` methods (and, public as in Shoelace, `focusOnTrigger()`, `getMenu()`, `updateAccessibleTrigger()`, `addOpenListeners()`, `removeOpenListeners()`, `handleOpenChange()` and the trigger handlers), the `sl-show`, `sl-after-show`, `sl-hide` and `sl-after-hide` events, the default and `trigger` slots, the `base`, `base__popup`, `trigger` and `panel` parts, the `dropdown.show` and `dropdown.hide` animations from the animation registry, and Shoelace's markup and styles (an `sl-popup` around the trigger slot and the panel) and keyboard, focus and ARIA behavior: Enter and Space toggle from the trigger, Arrow Down, Arrow Up, Home and End open the panel and focus a menu item, Escape and Tab close it, an outside mouse press closes it, and selecting a menu item closes it unless `stay-open-on-select` is set. Constructing a dropdown defines Velcro's `sl-popup` when that tag is not defined yet (the dependency is also registered by the entry), so the class-only entry needs no extra step. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): a disabled dropdown cannot be opened (the promise `show()` returns never settles) but disabling an open one does not close it, with the CloseWatcher API (for example Chromium) the panel's own Escape handler is not attached so the keydown from inside the panel is not stopped, `aria-haspopup` and `aria-expanded` go on the slotted trigger itself (on the inner button for an `sl-button` or `sl-icon-button`) and the panel wrapper's `aria-labelledby` names the popup, only a menu that is a direct child of the dropdown is found for the arrow keys, showing the dropdown again while it is closing leaves `open` true with the panel hidden, removing an open dropdown closes it with `sl-hide` and `sl-after-hide` on the detached element, and an outside mouse press does not close a dropdown whose `containingElement` was cleared. Shoelace's own dropdown tests (19) run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/dropdown-dir.tsx`). Shoelace's eight dropdown docs examples (HTML and React) are ported and live, each preview with room for the open panel. The React examples differ from Shoelace's only in their imports, with two disclosed exceptions: the hoisting snippet gains the `position: relative` its HTML example has, and the submenus snippet passes `style` as an object, because React rejects the string `style="max-width: 200px;"` Shoelace wrote. The menu docs page gains its "In Dropdowns" example, and the button group's dropdown and split button examples now use the live `sl-dropdown` and `sl-menu` instead of plain stand-ins. The upstream runner now also maps a test's `lit/decorators.js` import to the lit Velcro loads. Not implemented or unverified: the dark theme, right-to-left text, assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM), touch, and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/dropdown` and `@charm-ux/velcro/dropdown/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles, including the shared tabbable helpers.
