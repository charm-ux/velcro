Add a prototype `VelcroTabPanel`, registered as `sl-tab-panel` and built on the `@charm-ux/core` tab panel, with Shoelace 2.20.1's API (`name`, `active`, the default slot, the `base` part and the `--padding` custom property), markup and styles, and its behavior including its quirks (listed on the docs page under "Upstream quirks matched"): the `sl-tab-panel-<n>` id comes from a counter that advances on construction and is only written on connect, `role="tabpanel"` is set on every connect, `aria-hidden` is rewritten whenever `active` changes, and the `hidden` attribute does not hide an active panel. Shoelace's own tab panel tests run against it and all pass. Core's own tab coordination conflicts with Shoelace's model and is switched off rather than kept: core's `slot="tabpanel"` and `hidden` attributes and `transitionend` handling do not apply, its internal `visible` and `tab` properties are inert, and its `tab-show`, `tab-hide`, `tab-after-show` and `tab-after-hide` events are never emitted and not listed in the manifest. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them. Not implemented or unverified: `sl-tab-group` and `sl-tab`, so the docs example makes panels active with buttons and nothing sets `aria-labelledby`, the Shoelace React examples, and checks in Firefox, WebKit or with assistive technology (the product tests run in Chromium only). Registration is browser-only. Adds the `@charm-ux/velcro/tab-panel` and `@charm-ux/velcro/tab-panel/class` exports, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, behavior and styles.
