'@charm-ux/velcro': minor

Add a prototype `VelcroAvatar` (alias `SlAvatar`), registered as `sl-avatar` on top of the `@charm-ux/core` avatar, with Shoelace 2.20.1's API: the `image`, `label`, `initials`, `loading` and `shape` properties (only `shape` reflects; removing its attribute restores `circle`), the `sl-error` event when the image fails to load (a new `image` clears the error), the `icon` slot, the `base`, `icon`, `initials` and `image` parts and the `--size` custom property. Its markup and styles are Shoelace's: a `base` part with `role="img"` and the label, showing the image, else the initials, else the icon slot, whose fallback is the system library's `person-fill` `<sl-icon>`. The registering entry registers Velcro's `sl-icon` too, and, as with Shoelace's declared dependencies, constructing an avatar defines Velcro's `sl-icon` when that tag is not defined yet, so the class-only entry needs no extra step (an `sl-icon` another constructor owns is left in place, with Shoelace's version-mismatch warning when the versions differ). Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): the `hidden` attribute does not hide the avatar (core's base styles, which would hide it, are replaced by Shoelace's), an avatar without a label is an image with an empty accessible name, a failed image is not retried when the same URL is set again, initials are not shortened, and an unknown `shape` gives square corners. Core's reflected `image`, `label` and `initials` are redeclared as in Shoelace, and core's avatar parts, slots and `--avatar-*` properties are not rendered. Shoelace's own avatar test runs against it and passes. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). The docs examples (HTML and React) are Shoelace's with inline placeholder images in place of its remote photos, and the React images example gains a fragment because Shoelace's is not valid JSX. Not implemented or unverified: the dark theme, right-to-left text, when the browser defers a lazy image, and assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM). Registration is browser-only. Adds the `@charm-ux/velcro/avatar` and `@charm-ux/velcro/avatar/class` exports, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure and styles.
