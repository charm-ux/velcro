Add a prototype `VelcroDetails` (alias `SlDetails`), registered as `sl-details`, with Shoelace 2.20.1's API: the `open` and `disabled` properties (both reflect; assigning `null` restores the value the property held at the first attribute change, as in Shoelace's base element), the `summary` property, the `show()` and `hide()` methods (each returns a promise that settles on `sl-after-show` or `sl-after-hide`, or resolves to `undefined` at once when the details is already in that state or is disabled), the bubbling, composed `sl-show` and `sl-hide` events (cancelable; canceling keeps the details as it was) and `sl-after-show` and `sl-after-hide`, the default, `summary`, `expand-icon` and `collapse-icon` slots, and the `base`, `header`, `summary`, `summary-icon` and `content` parts. Core has no matching component (its accordion item has a different model: a `heading` attribute and slot, `accordion-item-*` parts and events, an `open` driven by the native toggle event and CSS transitions, no cancelable show and hide events and no animation registry), so it is built on the `@charm-ux/core` base element and takes Shoelace's markup and styles: a native `<details>` with a `<summary>` header, the keyboard handling (Enter and Space toggle, the arrow keys open and close) and the height animation. The `details.show` and `details.hide` animations come from the animation registry, with Shoelace's defaults, and the direction (the chevron icons, the `rtl` class and the animation's `rtlKeyframes`) is taken from the element's `dir` property when it is set, else from the document direction snapshot of Velcro's localization module, as Shoelace does. As with Shoelace's declared dependencies, constructing a details defines Velcro's `sl-icon` when that tag is not defined yet, so the class-only entry needs no extra step; an `sl-icon` another constructor owns is left in place, without Shoelace's version-mismatch warning. The registering entry registers Velcro's `sl-icon` up front with the same strict registration as the other registering entries, so it throws on import when another constructor owns `sl-icon` (a difference from Shoelace shared with them, to be resolved for all components together). Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"). The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). The docs page has all four of Shoelace's examples in Shoelace's order (Overview, Disabled, Customizing the Summary Icon and Grouping Details), each live, with React versions of the three that have one in Shoelace's docs. Not implemented or unverified: the dark theme, right-to-left layout, color contrast, and assistive technology. Registration is browser-only. Adds the `@charm-ux/velcro/details` and `@charm-ux/velcro/details/class` exports, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure and styles.
