Add a prototype `VelcroInput` (alias `SlInput`), registered as `sl-input` on top of the `@charm-ux/core` input, with Shoelace 2.20.1's API: the `type`, `name`, `value`, `defaultValue`, `size`, `filled`, `pill`, `label`, `help-text`, `clearable`, `disabled`, `placeholder`, `readonly`, `password-toggle`, `password-visible`, `no-spin-buttons`, `form`, `required`, `pattern`, `minlength`, `maxlength`, `min`, `max`, `step`, `autocapitalize`, `autocorrect`, `autocomplete`, `autofocus`, `enterkeyhint`, `spellcheck`, `inputmode` and `title` properties (with Shoelace's defaults and reflection: `type`, `size`, `filled`, `pill`, `disabled`, `readonly`, `form` and `required` reflect, and removing a reflected attribute restores its initial value, and the `value` attribute sets `defaultValue`), the `valueAsDate` and `valueAsNumber` accessors, the `focus()`, `blur()`, `select()`, `setSelectionRange()`, `setRangeText()`, `showPicker()`, `stepUp()`, `stepDown()`, `checkValidity()`, `reportValidity()`, `setCustomValidity()` and `getForm()` methods, the `validity` and `validationMessage` getters, the `sl-blur`, `sl-change`, `sl-clear`, `sl-focus`, `sl-input` and `sl-invalid` events, the `label`, `prefix`, `suffix`, `clear-icon`, `show-password-icon`, `hide-password-icon` and `help-text` slots, the `form-control`, `form-control-label`, `form-control-input`, `form-control-help-text`, `base`, `input`, `prefix`, `clear-button`, `password-toggle-button` and `suffix` parts, Shoelace's markup, styles and tokens, and its form participation (the `formdata`, `submit` and `reset` handling, the Enter key submit, the `data-valid` / `data-invalid` / `data-user-valid` / `data-user-invalid` / `data-required` / `data-optional` attributes, and the replaced `checkValidity()` and `reportValidity()` of the form). The clear and password toggle icons are Velcro's `<sl-icon>` from the `system` library; as in Shoelace, constructing an input defines `<sl-icon>` when no element owns that tag yet (an anonymous subclass when the icon class is already registered under another tag), and, as in Shoelace, a console warning is logged when another constructor of a different version owns the tag. The buttons' accessible names are the localized `clearEntry`, `showPassword` and `hidePassword` terms. Like Shoelace's, the element is not form-associated, does not delegate focus and has the `hidden` quirk. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"). Shoelace's own input test file (58 tests, including its axe check) runs against it and passes. The core `change` and `input` events are not emitted (Shoelace's `sl-change` and `sl-input` are) and core's keydown handling, styles, parts, markup, `start` and `end` slots, datalist support, number clamping and `--form-control-*` / `--input-*` properties do not apply. Velcro extensions kept from core and labelled as such in the API reference and types: `hide-label` and `error-message`; the core `invalid` and `label-position` properties are accepted and reflected but have no effect, the host carries core's `focusable` attribute and the core `ready` event is kept. `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; the read type stays core's `'ltr' | 'rtl' | 'auto'`). Types: `min`, `max` (`number | string`) and `step` (`number | 'any'`) have Shoelace's own types although the core input declares `number`, isolated by an internal typing layer and checked by compile-time tests (including negative ones) on the class and the generated React props; `autocorrect` is the exception, an accessor that reads as `any` and accepts only `'off' | 'on'` when assigned, because lib.dom's `HTMLElement` declares `autocorrect: boolean` and an `'off' | 'on'` property would stop the class being an `HTMLElement` for TypeScript (the manifest type is Shoelace's). Not implemented or unverified: the dark theme, right-to-left text, assistive technology beyond Shoelace's axe test, and the product tests ran in Chromium and WebKit locally (CI also runs Firefox). Registration is browser-only. Adds the `@charm-ux/velcro/input` and `@charm-ux/velcro/input/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
