Add prototype `VelcroTabGroup` (alias `SlTabGroup`) and `VelcroTab` (alias `SlTab`), registered as `sl-tab-group` and `sl-tab`, with Shoelace 2.20.1's API. The tab group has the `placement` (`top`, `bottom`, `start`, `end`), `activation` (`auto`, `manual`), `no-scroll-controls` and `fixed-scroll-controls` attributes (none reflected), the `show(panel)` method, the bubbling, composed, uncancelable `sl-tab-show` and `sl-tab-hide` events with `detail.name`, the `nav` and default slots, the `base`, `nav`, `tabs`, `active-tab-indicator`, `body`, `scroll-button`, `scroll-button--start`, `scroll-button--end` and `scroll-button__base` parts and the `--indicator-color`, `--track-color` and `--track-width` custom properties, with Shoelace's keyboard navigation (arrow keys by placement and direction, Home and End, Enter and Space for manual activation), `sl-icon-button` scroll buttons labelled with the localized `scrollToStart` and `scrollToEnd` terms, and Shoelace's mutation, resize and intersection observers. It is built on the `@charm-ux/core` base element, because core's tabs component has a different model (tabs in the default slot, panels in a `tabpanel` slot, `active-id` selection). The tab has the reflected `panel`, `active`, `closable` and `disabled` properties (and `tabIndex`), the `sl-close` event, the default slot and the `base`, `close-button` and `close-button__base` parts; it extends the `@charm-ux/core` tab with core's tab coordination switched off (core's `selected` property has no attribute and no effect and is labelled as a Velcro extension). As with Shoelace's declared dependencies, constructing a tab defines Velcro's `sl-icon-button`, and constructing a tab group defines Velcro's `sl-icon-button` and `sl-resize-observer`, when those tags are not defined yet (another owner of the tag is left in place, without Shoelace's version-mismatch warning). Importing the tab group applies Shoelace's `scrollend` polyfill, as in Shoelace; the polyfill module is listed in the package's `sideEffects` so bundlers keep it. Shoelace's behavior is matched including its quirks (listed on the docs pages under "Upstream quirks matched"), among them: `placement` is not reflected, the first tab is only selected once the group is visible, setting `active` to false on the active tab leaves no tab active while its panel stays shown, the scroll buttons and close buttons cannot be reached with the keyboard, the tab's `role` and ARIA attributes replace the page's values, and a removed reflected attribute restores the value from the first attribute change. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`); the tab group resolves its direction from its own `dir` (attribute or property), else `<html dir>`, as Shoelace does. The React wrapper's `onSlTabShow` and `onSlTabHide` callbacks are typed `CustomEvent<{ name: string }>`, as Shoelace's event types are. The tab group docs page has all eight of Shoelace's examples in Shoelace's order, each live with a React version; the tab panel page's overview now uses Shoelace's own example with the tab group. Not implemented or unverified: the dark theme, right-to-left scroll buttons, color contrast and assistive technology (the accessibility-tree checks are Playwright's ARIA snapshots, computed from the DOM). Registration is browser-only. Adds the `@charm-ux/velcro/tab-group`, `@charm-ux/velcro/tab-group/class`, `@charm-ux/velcro/tab` and `@charm-ux/velcro/tab/class` exports, the vendored Shoelace test files to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure and styles.
