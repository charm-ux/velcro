Add the Shoelace 2.20.1 dark theme (`@charm-ux/velcro/themes/dark.css`, selectors `:host` and `.sl-theme-dark`) and complete the light theme (`@charm-ux/velcro/themes/light.css`) to the full Shoelace 2.20.1 token set. Both files are copies of the upstream theme files with a provenance header; the light theme is therefore NOT visually unchanged: every token now has the upstream value. Visible differences in light, now matching Shoelace: button text is 14px (medium), 12px (small) and 16px (large), where it was 16px, 14px and 20px; the small and large button radii are 4px (were 3px and 5.5px); `--sl-font-sans` is the full upstream stack; and the transition-duration and focus-ring tokens now have their upstream values. A product spec pins each file's content to the upstream SHA-256, checks that both themes define the same tokens, and checks that card, badge, button, progress bar and skeleton resolve Shoelace's dark colors under `.sl-theme-dark` and Shoelace's light colors by default, plus the button font size and radius per size. Dark rendering is token-checked, not screenshot-checked, and only the examples above were exercised. Load `dark.css` after `light.css`: both rules have equal specificity on `.sl-theme-*` and `:root`, so the later sheet wins on the same element. The docs example iframes now include the dark rules (still light by default); the site-wide toggle is not part of this change.
