Ship a Custom Elements Manifest and generated React wrappers.

- `@charm-ux/velcro` now ships `custom-elements.json` (the `customElements` field and the `./custom-elements.json`
  export), regenerated by the library build. It lists each component's own API and the API inherited from
  `@charm-ux/core`, with every inherited member, attribute and event naming its core class and package. Core's
  template-bound slots, parts and CSS custom properties are not inherited, because every Velcro component renders its
  own template. The `@status` tag and the CSS custom property defaults are now part of the JSDoc.
- The build also generates React wrappers and JSX types from the manifest under `dist/react` (exports `./react` and
  `./react/*`), and type-checks the `sl-button` wrapper against Shoelace's props and events. The wrappers import
  `react`, which is not a dependency of the package. React's own `onFocus`/`onBlur` props cover the native focus and
  blur events, which are therefore not generated as event props.
- JSDoc only: the `ready` event is no longer declared by five components themselves; it is inherited from core, which
  is where it comes from. The button documents its `button-control` part. No runtime behavior changes.
- Docs: every component page's API tables (attributes and properties, methods, events, slots, parts, CSS custom
  properties) are generated from the manifest, with inherited rows marked with their origin. A browser test fails
  when a page's tables drift from the manifest.
- `docs/api-parity.md` compares every documented Shoelace 2.20.1 API entry of the implemented components with the
  manifest; the gaps are a ledger that may only shrink.
