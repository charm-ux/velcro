Add prototype `VelcroRange` (alias `SlRange`), registered as `sl-range` and built on the `@charm-ux/core` base element (core has no range), with Shoelace 2.20.1's API: the non-reflected `name`, `value`, `label`, `helpText` (`help-text`), `min`, `max`, `step`, `tooltip` (`top`, `bottom` or `none`) and `tooltipFormatter`, the reflected `disabled` and `form` (restored to their initial value when set to null or undefined, as Shoelace's base element does), `defaultValue` (which follows the `value` attribute and is what a form reset restores), the public `input` and `output` queries and `title`, `focus()`, `blur()`, `stepUp()`, `stepDown()`, `checkValidity()`, `reportValidity()`, `setCustomValidity()`, `getForm()` and the `validity` and `validationMessage` getters, the `sl-focus`, `sl-blur`, `sl-input`, `sl-change` and `sl-invalid` events, the `label` and `help-text` slots, the `form-control`, `form-control-label`, `form-control-input`, `form-control-help-text`, `base`, `input` and `tooltip` parts and the `--thumb-size`, `--tooltip-offset`, `--track-color-active`, `--track-color-inactive`, `--track-height` and `--track-active-offset` custom properties. Shoelace's markup and styles are used unchanged: the native `<input type="range">` with its own keyboard handling, a progress track drawn from `--percent`, a tooltip `<output>` shown while the range has the focus or is pressed and placed over the thumb by Shoelace's estimate (mirrored in right-to-left, which follows the range's `dir` property or the document's direction), and form participation through the shared form-control controller (name and value in the form's data, validation, `data-*` validity attributes, reset). Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): removing the `value`, `min`, `max`, `step`, `label`, `help-text`, `name` or `tooltip` attribute sets the property to null, and a null `value` makes the next render throw; a range disconnected before its first render throws from `disconnectedCallback`; the tooltip hides on the mouse or touch release even though the range keeps the focus; the reflected `form` attribute is always present; changing `min` or `max` does not re-clamp `value`; `--percent` carries floating-point noise; and the methods that use the inner input throw before the first render. Shoelace's own range tests (37) run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/range-dir.tsx`). The range has no translatable text. Shoelace's ten range examples (HTML and React) are ported and live; the React examples differ from Shoelace's only in their imports. Not implemented or unverified: the dark theme, assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM), pixel comparison with Shoelace, and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/range` and `@charm-ux/velcro/range/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
