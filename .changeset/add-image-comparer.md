Add prototype `VelcroImageComparer` (alias `SlImageComparer`), registered as `sl-image-comparer` and built on the `@charm-ux/core` base element (core has no image comparer), with Shoelace 2.20.1's API: the reflected `position` (default 50, restored to its initial value when set to null or undefined, as Shoelace's base element does), the public `base` and `handle` queries and `handlePositionChange()`, the `sl-change` event, the `before`, `after` and `handle` slots, the `base`, `before`, `after`, `divider` and `handle` parts and the `--divider-width` and `--handle-size` custom properties. Shoelace's markup and styles are used unchanged: the after image is clipped to the position, and the divider holds a `role="scrollbar"` handle (`tabindex="0"`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-controls`) with a system `grip-vertical` `sl-icon`; the divider follows a mouse or touch drag (rounded to two decimals, clamped to 0-100) and the arrow keys (by 1, by 10 with Shift, swapped in right-to-left), Home and End. Constructing an image comparer defines Velcro's `sl-icon` when that tag is not defined yet (the dependency is also registered by the entry), so the class-only entry needs no extra step; this differs from Shoelace, which documents `sl-icon` as the dependency but declares it in a `static scopedElement` field its base element never reads, so its own entry leaves `sl-icon` undefined. Shoelace's behavior is otherwise matched including its quirks (listed on the docs page under "Upstream quirks matched"): `sl-change` is emitted for every change of `position` after the first update, including changes from script and attributes, once per update; a `position` set by attribute or property is not clamped; the keys are handled on the base element, so they also act while focus is on slotted content; with `dir="auto"` the left and right arrows do nothing; a drag starts on `mousedown` or `touchstart` and moves the divider only from the first `pointermove`, any mouse button starts it, pressing the handle does not focus it, and the width is measured once when the drag starts; Shoelace's styles for slotted images never match, so images stay inline and are not scaled down; and the handle has no accessible name. Shoelace's own image comparer tests (12) run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/image-comparer-dir.tsx`). Shoelace's two image comparer examples (HTML and React) are ported and live, with inline placeholder images instead of Shoelace's third-party photos; the React examples otherwise differ from Shoelace's only in their imports. Not implemented or unverified: the dark theme, assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM), a real touch device (touch is checked with synthetic events), and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/image-comparer` and `@charm-ux/velcro/image-comparer/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
