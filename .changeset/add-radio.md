Add a prototype `VelcroRadio` (alias `SlRadio`), registered as `sl-radio` on top of the `@charm-ux/core` radio through Velcro's local scope resolver, with Shoelace 2.20.1's API: the `checked` property (internal state, not an attribute), `value` (not reflected), `size` (`small`, `medium`, `large`) and `disabled`, the `handleCheckedChange()` and `handleDisabledChange()` methods, the `sl-focus` and `sl-blur` events, the default (label) slot and the `base`, `control`, `control--checked`, `checked-icon` and `label` parts. A checked radio renders the system library's `radio` icon in an `<sl-icon>`, so the radio's entry also registers Velcro's icon. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): a `checked` attribute is ignored, a click checks but never unchecks and a standalone radio ignores Space and the arrow keys, every connect rewrites `role`, `tabindex="-1"` and `aria-disabled` (also on a checked radio), a disabled radio keeps its checked state and tab stop, the `hidden` attribute does not hide it, and the invalid `align-items: top` declaration is kept. The `disabled` and `checked` watchers run in Shoelace's order (disabled first) and receive the previous and current values, and `autofocus` is the platform's own property, as in Shoelace. Core extras are kept as Velcro extensions that change nothing unless set: `readonly`, `label` (slot fallback text), `hide-label`, `vertical` and the `selected` and `ready` events; core's Space-key handling, its unchecking of a radio that becomes disabled, its reactive `autofocus` property and its `radio-*` parts and `--radio-*` custom properties are not used. `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's). The docs examples and their React ports put the radios in Velcro's `<sl-radio-group>`, as Shoelace's do, and Shoelace's one radio test passes against Velcro. The product tests run in Chromium and WebKit locally and in Firefox in CI. Registration is browser-only. The manifest no longer lists an inherited core attribute for a property a Velcro class redeclares without one (here `checked`), so the API table shows `checked` as a property only. Adds the `@charm-ux/velcro/radio` and `@charm-ux/velcro/radio/class` exports and the radio's third-party notice for adapted Shoelace (MIT) wording, structure and styles.
