Fix: importing a registering entry no longer throws on a tag clash. Every tag Velcro registers, a component's own and those of the elements it renders (button's `sl-spinner`, the `sl-icon` of avatar, checkbox, icon button, input and radio, radio group's `sl-button-group`, the `sl-icon-button` and `sl-icon` of alert, tab and tag, tab group's `sl-icon-button`, `sl-icon` and `sl-resize-observer`, tooltip's `sl-popup`), is now registered exactly as Shoelace 2.20.1's `define` registers it. A tag that another constructor already owns (another library, a second copy of Velcro) is left in place, and Shoelace's console warning (`Attempted to register <sl-x> (unknown version), but <sl-x> v2.20.1 has already been registered.`) is logged when the two constructors' versions differ; Velcro's classes declare no version, so the warning appears only when the existing one declares one, such as Shoelace's own elements. A class the platform refuses because it is already registered under another tag is registered as an anonymous subclass of it. Before, importing an entry threw in both cases. Constructing a component that registers its dependencies on construction follows the same rules. Velcro still registers a component's dependencies when its entry is imported, where Shoelace registers them when the first element is constructed.
