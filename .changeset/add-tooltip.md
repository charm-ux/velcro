Add a prototype `VelcroTooltip` (alias `SlTooltip`), registered as `sl-tooltip` on top of the `@charm-ux/core` tooltip, with Shoelace 2.20.1's API: the `content`, `placement`, `disabled`, `distance`, `open`, `skidding`, `trigger` and `hoist` properties (with Shoelace's defaults; `disabled` and `open` reflect, and removing either attribute restores its initial value), the `show()` and `hide()` methods (promises that settle on the after-events), the `sl-show`, `sl-after-show`, `sl-hide` and `sl-after-hide` events, the default and `content` slots, the `base`, `base__popup`, `base__arrow` and `body` parts, the `--max-width`, `--show-delay` and `--hide-delay` custom properties, and Shoelace's markup (an `<sl-popup>` with flip, shift, arrow and hover bridge), styles and tokens. The hover, focus, click and manual triggers, the delays, Escape (through `CloseWatcher` where available) and the `tooltip.show` / `tooltip.hide` animations from the animation registry follow Shoelace. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"). Shoelace's own tooltip test file (9 tests, none of them an accessibility check) runs against it and passes. As in Shoelace, a tooltip rendered with `open` already set ignores Escape until it is closed and opened again, and the `rtlKeyframes` variant follows the `dir` property, else the document's direction. The tooltip renders Velcro's `<sl-popup>`; as in Shoelace, constructing a tooltip defines it when no element owns that tag yet, so the class-only entry needs no extra registration. The core `tooltip-*` events are not emitted and core's styles, live region and custom properties do not apply. Velcro extensions kept from core and labelled as such: `fixed-placement` (the fixed positioning strategy, like `hoist`) and `toggle()`; the core `arrow` and `anchor` properties are accepted but have no effect, and the core `ready` event is kept. `dir` and `lang` are declared as Shoelace's base element declares them. Not implemented or unverified: the dark theme, right-to-left layout, assistive technology, and any automated accessibility (axe) check; the product tests run in Chromium, Firefox and WebKit. Registration is browser-only. Adds the `@charm-ux/velcro/tooltip` and `@charm-ux/velcro/tooltip/class` exports, the React wrapper, the docs page with Shoelace's examples and their React versions, the vendored Shoelace test file to the conformance suite, and the third-party notice for adapted Shoelace (MIT) wording, structure, behavior and styles. The docs pages that said Velcro had no `sl-tooltip` now say their examples predate it.
