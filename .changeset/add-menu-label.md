Add a prototype `VelcroMenuLabel`, registered as `sl-menu-label` and built on the `@charm-ux/core` base element (core has no menu label), with Shoelace 2.20.1's API (the default slot and the `base` part; the component has no attributes, events or custom properties of its own), markup and styles, and its behavior including its one quirk (listed on the docs page under "Upstream quirks matched"): the `hidden` attribute does not hide the label, because the host's own `display: block` outranks the browser's `[hidden]` rule. Core's base styles, which would hide it, are replaced by Shoelace's. Shoelace's own menu label test runs against it and passes. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them: at runtime they are plain reactive properties, and the `dir` setter accepts any string, but its read type, and the manifest, React and JSX types generated from it, stay core's `'ltr' | 'rtl' | 'auto'` (narrower than Shoelace's `string`; fixing it needs a core change). Not implemented or unverified: `sl-menu` and `sl-menu-item`, so the docs examples (HTML and React) use plain styled elements for the menu and its items, and checks inside a real menu, with right-to-left text or with assistive technology. Registration is browser-only. Adds the `@charm-ux/velcro/menu-label` and `@charm-ux/velcro/menu-label/class` exports, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure and styles.
