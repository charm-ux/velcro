Add a prototype `VelcroAnimation` (alias `SlAnimation`), registered as `sl-animation` and built on the `@charm-ux/core` base element (there is no core animation), with Shoelace 2.20.1's API: `name`, `play`, `delay`, `direction`, `duration`, `easing`, `end-delay`, `fill`, `iterations`, `iteration-start`, `keyframes`, `playback-rate` and `currentTime`, the `cancel()`, `finish()` and (public, as in Shoelace) `render()` methods, the `sl-start`, `sl-finish` and `sl-cancel` events and the default slot, whose first element is animated with the Web Animations API. The 98 animations and 29 easings are Velcro's own copy of `@shoelace-style/animations` 1.2.0 (the version Shoelace 2.20.1's lockfile resolves, values unchanged; no Shoelace package is a dependency). `presets/SOURCE.json` pins npm's published sha512 integrity for that package and the sha256 of each tarball file, and a test fails if the vendored data differs from the package's, and `getAnimationNames()` and `getEasingNames()` are exported from the package root, `@charm-ux/velcro/animation` and `@charm-ux/velcro/animation/class`. Shoelace's module paths have non-registering counterparts: `@charm-ux/velcro/utilities/animation` (its `dist/utilities/animation.js`: the two utilities) and `@charm-ux/velcro/animation/animations` (its `dist/components/animation/animations.js`: the `animations` namespace and the two utilities); neither loads the component or the core base element, and nothing new is added to the package root. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): a playing animation emits `sl-start` twice when first connected, each animation property changed in the same update recreates the animation once more, an `iterationStart` change after the first update is not applied until something else recreates the animation, `finish()` throws while `iterations` is infinite, `cancel()` leaves the animation paused at time 0 with its first keyframe applied, an unknown name or `none` leaves the previous animation running, disconnecting cancels without `sl-cancel` and keeps `play`, a rejected easing (including one named after an `Object.prototype` member) only surfaces as an unhandled rejection, `name="easings"` animates nothing, and assigning `null` to `play` restores its recorded initial value. Shoelace's own animation tests run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). Shoelace's four React examples are ported to Velcro's generated React wrappers (only their import lines change) and run in React 19 by the product tests. Not implemented or unverified: `sl-select`, `sl-option` and `sl-input` (the Animations & Easings example uses native controls), `prefers-reduced-motion` handling (Shoelace has none either), and Firefox, WebKit and assistive technology checks (the gated product tests run in Chromium only). Registration is browser-only. Adds the `@charm-ux/velcro/animation`, `@charm-ux/velcro/animation/class`, `@charm-ux/velcro/animation/animations` and `@charm-ux/velcro/utilities/animation` exports (the export gate accepts the last two only with their exact targets while the animation is in the catalog), React example sources (`examples/**/*.jsx`) shown on docs pages, the vendored Shoelace test file to the conformance suite (the upstream runner now maps a test's bare `lit` import to the lit Velcro loads), keeps the docs `velcro` entry's exports so examples can import the utilities, and updates the third-party notices for adapted Shoelace (MIT) code and the copied `@shoelace-style/animations` (MIT) and animate.css (MIT) keyframes.
