Add a prototype `VelcroInclude`, registered as `sl-include` and built directly on the `@charm-ux/core` base element (there is no core include), with Shoelace 2.20.1's API (`src`, `mode`, `allow-scripts`, the `sl-load` and `sl-error` events with `detail.status`), its content and styles, and its behavior including its quirks (listed on the docs page under "Upstream quirks matched"): responses, failed ones included, are cached by `src` for the life of the page and the cache ignores `mode`; only `src` starts a request; a response for a superseded `src` emits no event, but a superseded request that fails outright still emits `sl-error` with status -1, and `src` A, then B, then A again loads A twice; any exception emits `sl-error` with status -1, and a `no-cors` response from another origin is opaque and ends in status 0; no property reflects, so removing `src` requests `null` and removing `mode` breaks the next request; the `hidden` attribute does not hide an include. Shoelace's own include tests run against it and all pass. The request function Shoelace publishes at `dist/components/include/request.js` is exported as `requestInclude` at `@charm-ux/velcro/include/request` and shares the elements' cache (as in Shoelace it is not exported from the package root or `@charm-ux/velcro/include`). The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them: at runtime they are plain reactive properties, and the `dir` setter accepts any string, but its read type, and the manifest, React and JSX types generated from it, stay core's `'ltr' | 'rtl' | 'auto'` (narrower than Shoelace's `string`; fixing it needs a core change). Included content is inserted as HTML without sanitizing, as in Shoelace. The docs examples include a fixture file the documentation site serves instead of Shoelace's remote file, and add an `allow-scripts` example. Not implemented or unverified: checks in Firefox or with assistive technology (the product tests run in Chromium; the product include tests also passed once in WebKit). Registration is browser-only. Adds the `@charm-ux/velcro/include`, `@charm-ux/velcro/include/class` and `@charm-ux/velcro/include/request` exports, the vendored Shoelace test file to the conformance suite, the `./include/request` entry of the exact-key module export table in the catalog gate (required while include is in the catalog), and updates the third-party notices for adapted Shoelace (MIT) wording, behavior and styles.
