Add prototype `VelcroRating` (alias `SlRating`), registered as `sl-rating` and built on the `@charm-ux/core` base element (core has no rating), with Shoelace 2.20.1's API: the non-reflected `label` (rendered as the slider's `aria-label`), `value`, `max`, `precision` and `getSymbol` (a function returning trusted HTML, by default a system `star-fill` `sl-icon`), the reflected `readonly` and `disabled` (restored to their initial value when set to null or undefined, as Shoelace's base element does), the public `rating` query, `focus()` and `blur()`, the `sl-change` and `sl-hover` (`{ phase, value }`) events, the `base` part and the `--symbol-color`, `--symbol-color-active`, `--symbol-size` and `--symbol-spacing` custom properties. Shoelace's markup and styles are used unchanged: a `role="slider"` element with `aria-valuenow`, `aria-valuemin` and `aria-valuemax`, a row of symbols with partial values drawn as two clipped layers, pointer and touch selection rounded up to `precision`, the arrow keys (by `precision`, by 1 with Shift, swapped in right-to-left), Home and End, and a click on the current value that clears it. Constructing a rating defines Velcro's `sl-icon` when that tag is not defined yet (the dependency is also registered by the entry), so the class-only entry needs no extra step. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): connecting a rating emits `sl-hover` twice (`end`, then `move`, both with value 0) without any pointer; a click on a readonly rating and the end of a touch on a disabled or readonly rating emit `sl-change` without changing the value; hovering a disabled or readonly rating still emits `sl-hover`; the arrow keys bound each step on one side only, so a value set out of range from script moves one step and stays out of range; the default `label` is an empty string, so the slider has `aria-label=""`; removing the `value`, `max` or `precision` attribute sets the property to null; a `getsymbol` attribute replaces the function with a string and breaks rendering; and with `dir="auto"` the left and right arrows do nothing. Shoelace's own rating tests (11) run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/rating-dir.tsx`). The label is not localized (Shoelace 2.20.1 has no translation term for it). Shoelace's ten rating examples (HTML and React) are ported and live; the React examples differ from Shoelace's only in their imports, so Shoelace's React Detecting Hover example still throws a `ReferenceError` on each `sl-hover` event, as it does in Shoelace. Not implemented or unverified: the dark theme, assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM), a real touch device (touch is checked with synthetic events), and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/rating` and `@charm-ux/velcro/rating/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
