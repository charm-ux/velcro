'@charm-ux/velcro': minor
---

Register `sl-button` and `sl-spinner` by defining the exported `VelcroButton` and `VelcroSpinner` classes themselves through the native custom element registry, instead of core's `registerComponent` subclass. `customElements.get('sl-button') === VelcroButton`, `new VelcroButton()` works once registered, and Velcro no longer changes core's page-wide `ch` prefix, so core's own button can load before or after Velcro. A tag that another constructor already owns is left in place, as Shoelace's `define` leaves it. Adds class-only exports that register no element `@charm-ux/velcro/button/class` and `@charm-ux/velcro/spinner/class` and the aliases `SlButton` and `SlSpinner` (the same classes as `VelcroButton` and `VelcroSpinner`) on every entry. The root and `./button`/`./spinner` entries still register. Limits: the package root's four registered components (the badge and divider are added by a separate change) are checked together in Chromium, while class-only entries and aliases exist only for button and spinner; scope-dependent core features (declared dependencies, scope-aware templates) and nested core components are not supported (a component that uses them fails when it is created, even alone on the page) and not tested, server-side rendering is not supported, and core's `button` base-name attribute is no longer set on `sl-*` elements.
