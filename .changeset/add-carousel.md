Add a prototype `VelcroCarousel` and `VelcroCarouselItem` (aliases `SlCarousel` and `SlCarouselItem`), registered as `sl-carousel` and `sl-carousel-item` and built on the `@charm-ux/core` base element (core has no carousel), with Shoelace 2.20.1's API: `loop`, `navigation`, `pagination`, `autoplay`, `autoplay-interval`, `slides-per-page`, `slides-per-move`, `orientation` and `mouse-dragging`; `previous()`, `next()` and `goToSlide()`; the `sl-slide-change` event (with Shoelace's `SlSlideChangeEvent` type exported and its `GlobalEventHandlersEventMap` entry, so `addEventListener('sl-slide-change', ...)` infers the detail); the `previous-icon` and `next-icon` slots; the `base`, `scroll-container`, `pagination`, `pagination-item`, `pagination-item--active`, `navigation`, `navigation-button`, `navigation-button--previous` and `navigation-button--next` parts; and the `--slide-gap`, `--aspect-ratio` and `--scroll-hint` custom properties. The markup, scroll-snap layout, looping clones, intersection-observer syncing, autoplay controller, mouse dragging, keyboard handling and localized labels are Shoelace's. The navigation buttons draw Velcro's `<sl-icon>`, which the registering entry registers and constructing a carousel defines when the tag is free; the carousel applies the tab group's copy of Shoelace's scrollend polyfill. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): the `hidden` attribute does not hide a carousel or an item, the carousel overwrites the host's role and label and its slides' roles, labels, ids, `aria-hidden` and `inert`, the dots' `aria-controls` cannot resolve across the shadow boundary, looping adds real `data-clone` children, the unavailable navigation buttons are only `aria-disabled`, no slide has `--is-active` until the active slide changes, nothing is restored when a reflected property is set to null, `slides-per-move` is lowered but never raised, and autoplay does not follow an interval change or a reconnect. Shoelace's own carousel and carousel item tests run against them and all pass (two upstream skips: autoplay advancing and mouse dragging, which the product tests cover). The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). The docs examples (HTML and React) are Shoelace's with inline placeholder images in place of its Unsplash photographs; several of Shoelace's React examples did not run as written and carry minimal corrections, listed on the docs page. Not implemented or unverified: touch scrolling, the dark theme, assistive technology, and Firefox here (WebKit does not report pointer movement, so mouse dragging does not scroll there). Registration is browser-only. Adds the `@charm-ux/velcro/carousel`, `@charm-ux/velcro/carousel/class`, `@charm-ux/velcro/carousel-item` and `@charm-ux/velcro/carousel-item/class` exports, the vendored Shoelace test files to the conformance suite (the upstream runner now maps a test's `lit/directives/<name>.js` import to the lit Velcro loads), and updates the third-party notices for adapted Shoelace (MIT) code.
