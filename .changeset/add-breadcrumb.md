Add prototype `VelcroBreadcrumb` (alias `SlBreadcrumb`) and `VelcroBreadcrumbItem` (alias `SlBreadcrumbItem`), registered as `sl-breadcrumb` and `sl-breadcrumb-item` and built on the `@charm-ux/core` base element (core's breadcrumb and breadcrumb item are a different model: a `role="list"` wrapper, a link-only, focusable item with reflected `href`, `current` and `separator` attributes), with Shoelace 2.20.1's API. The breadcrumb has the non-reflected `label` (rendered as the `<nav>`'s `aria-label`), the public `defaultSlot` and `separatorSlot` queries, the default and `separator` slots and the `base` part; it clones the first separator element (a system chevron `sl-icon` by default, `chevron-left` in right-to-left) into each item's `separator` slot with its ids removed and a `data-default` marker, leaves an item's own separator alone, sets `aria-current="page"` on the last item, and regenerates the default separators when the breadcrumb's or the document's direction changes. The item has the non-reflected `href`, `target` and `rel` (default `noreferrer noopener`), the public `defaultSlot`, `hrefChanged()` and `handleSlotChange()`, the default, `prefix`, `suffix` and `separator` slots and the `base`, `label`, `prefix`, `suffix` and `separator` parts, and renders its label as a link (with `href`), a `<div>` wrapper (around a slotted `sl-dropdown`) or a `<button type="button">`. Shoelace's markup and styles are used unchanged. Constructing a breadcrumb defines Velcro's `sl-icon` when that tag is not defined yet (the dependency is also registered by the entry), so the class-only entry needs no extra step; the item has no dependencies, and each entry registers only its own component, as in Shoelace. Shoelace's behavior is matched including its quirks (listed on the docs pages under "Upstream quirks matched"): the default `label` is an empty string, so the `<nav>` has `aria-label=""`; only the first separator element is used, and replacing the separator later does not update the items until the default slot changes; `aria-current` goes on the item element and only `sl-breadcrumb-item` children count; the breadcrumb host has no display rule; an item with `href` but no label content stays a button; the link gets `target` and `rel` only when `target` is set; and the empty prefix and suffix containers are laid out because the later `display: flex` overrides `display: none`. Shoelace's own breadcrumb (8) and breadcrumb item (18) tests run against them and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/breadcrumb-dir.tsx`). The label is not localized (Shoelace 2.20.1 has no translation term for it). Shoelace's seven breadcrumb examples and its breadcrumb item example (HTML and React) are ported and live; the React examples differ from Shoelace's only in their imports. Not implemented or unverified: the dark theme, assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM), touch, and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/breadcrumb`, `@charm-ux/velcro/breadcrumb/class`, `@charm-ux/velcro/breadcrumb-item` and `@charm-ux/velcro/breadcrumb-item/class` exports, the React wrappers, the vendored Shoelace test files to the conformance suite (whose public CI summary now prints a pinned test title longer than 200 characters whole, as some of the breadcrumb's are, as long as its whole public line fits the 300 characters the CI log keeps; otherwise it says 'unlisted title'), and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
