Add prototype `VelcroMenu` and `VelcroMenuItem` (aliases `SlMenu` and `SlMenuItem`), registered as `sl-menu` and `sl-menu-item` and built on the `@charm-ux/core` base element, with Shoelace 2.20.1's API, markup and styles. The menu is an inline list with `role="menu"`, a roving tab index, the `sl-select` event (its detail is `{ item }`; checkbox items are toggled first), Enter, Space, Down, Up, Home and End. The item has `type` (`normal` or `checkbox`), `checked`, `value`, `loading` and `disabled` (`checked`, `loading` and `disabled` reflect), the `prefix`, `suffix` and `submenu` slots, the `base`, `checked-icon`, `prefix`, `label`, `suffix`, `spinner`, `spinner__base` and `submenu-icon` parts, `--submenu-offset`, `getTextLabel()`, `isSubmenu()` and nested submenus in an `sl-popup` (hover after 100 ms, Right, Enter or Space to enter, Left, Escape and Tab to leave). Shoelace's behavior is matched including its quirks (listed on both docs pages under "Upstream quirks matched"): there is no type-to-select although Shoelace's page promises it, a loading item still emits `click` and `sl-select`, `checked` on a non-checkbox item is reset with a `console.error` (Shoelace's own React Value & Selection example, ported verbatim, triggers it on every selection), the keys act on the tab-stop item rather than the focused one (hovering focuses an item without moving the tab stop), any slotted change resets the roving tab stop to the first item, a `menuitemradio` element is navigated to but its click is ignored, the submenu click handler's `tagName` comparison never matches, and the safe triangle drawn while a submenu is open has a vertex at the viewport's top-left corner until the pointer has moved over the item (so a pointer resting at 0,0 hovers the item and its hover handler takes the focus back from a submenu a key press just opened). Core's menu and menu item (a dropdown and a link-or-span item) are a different model and are not extended; the core `ready` event is kept and labelled as a Velcro extension, and `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). `sl-menu-item` registers `sl-icon`, `sl-popup` and `sl-spinner` too. Constructing an item defines them when they are not defined yet, and the registering entry defines them when it is imported; a tag that another constructor already owns is left alone (with Shoelace's console warning when the versions differ) and an anonymous subclass is defined when the platform refuses the class itself, so importing never throws on a tag clash. Shoelace's own menu (6) and menu item (12) tests run against them and pass. All of Shoelace's menu and menu item docs examples are ported (HTML and React) except "In Dropdowns", which needs `sl-dropdown`, not implemented yet; the menu label page now uses the live menu. The custom elements manifest build maps an event detail that names another Shoelace class (`SlMenuItem`) to Velcro's class in the generated React and JSX types. Not implemented or unverified: `sl-dropdown` (so a menu in a dropdown is unexercised), the submenu safe triangle, edge repositioning, right-to-left and touch, the dark theme, and Firefox and assistive technology checks (the product tests were run in Chromium and WebKit; Firefox runs in CI). Registration is browser-only. Adds the `@charm-ux/velcro/menu`, `@charm-ux/velcro/menu/class`, `@charm-ux/velcro/menu-item` and `@charm-ux/velcro/menu-item/class` exports, the vendored Shoelace test files to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
