Add a prototype `VelcroCheckbox` (alias `SlCheckbox`), registered as `sl-checkbox` on top of the `@charm-ux/core` checkbox, with Shoelace 2.20.1's API: the `name`, `value`, `size`, `disabled`, `checked`, `indeterminate`, `defaultChecked`, `form`, `required`, `help-text` and `title` properties (with Shoelace's defaults and reflection: `size`, `disabled`, `checked`, `indeterminate`, `form` and `required` reflect, removing a reflected attribute restores its initial value, and the `checked` attribute sets `defaultChecked`), the `click()`, `focus()`, `blur()`, `checkValidity()`, `getForm()`, `reportValidity()` and `setCustomValidity()` methods, the `validity` and `validationMessage` getters, the `sl-blur`, `sl-change`, `sl-focus`, `sl-input` and `sl-invalid` events, the default and `help-text` slots, the `base`, `control`, `control--checked`, `control--indeterminate`, `checked-icon`, `indeterminate-icon`, `label` and `form-control-help-text` parts, Shoelace's markup, styles and tokens, and its form participation (the `formdata`, `submit` and `reset` handling, the `data-valid` / `data-invalid` / `data-user-valid` / `data-user-invalid` / `data-required` / `data-optional` attributes, and the replaced `checkValidity()` and `reportValidity()` of the form). The checked and indeterminate icons are Velcro's `<sl-icon>` from the `system` library; as in Shoelace, constructing a checkbox defines `<sl-icon>` when no element owns that tag yet (an anonymous subclass when the icon class is already registered under another tag), so the class-only entry needs no extra registration. Like Shoelace's, the element is not form-associated and does not delegate focus. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): the `hidden` attribute does not hide the checkbox, `form=""` is always reflected, `aria-describedby` always points at the help text, the inner checkbox's `aria-checked` ignores `indeterminate`, and a form reset leaves `indeterminate` as it is. Shoelace's own checkbox test file (42 tests, including its axe check) runs against it and passes. The core `change` and `input` events are not emitted (Shoelace's `sl-change` and `sl-input` are) and core's styles, markup and `--form-control-*` properties do not apply. Velcro extensions kept from core and labelled as such in the API reference and types: `readonly`, `label`, `hide-label` and `error-message`; the core `invalid`, `label-position` and `autofocus` properties are accepted and reflected but have no effect, the host carries core's `focusable` attribute and the core `ready` event is kept. `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; the read type stays core's `'ltr' | 'rtl' | 'auto'`). Not implemented or unverified: the dark theme, right-to-left text and assistive technology beyond Shoelace's axe test; the product tests were run locally in Chromium and WebKit (Firefox runs in CI). Registration is browser-only. Adds the `@charm-ux/velcro/checkbox` and `@charm-ux/velcro/checkbox/class` exports, the React wrapper, the docs page with Shoelace's examples and their React versions, the vendored Shoelace test file to the conformance suite, and the third-party notice for adapted Shoelace (MIT) wording, structure, behavior and styles.
