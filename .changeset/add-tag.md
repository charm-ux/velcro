Add a prototype `VelcroTag` (alias `SlTag`), registered as `sl-tag`, with Shoelace 2.20.1's API: the `variant` (`primary`, `success`, `neutral`, `warning`, `danger` and `text`), `size` (`small`, `medium`, `large`), `pill` and `removable` properties (`variant`, `size` and `pill` reflect, and removing one of their attributes restores its default), the bubbling, composed, uncancelable `sl-remove` event, the default slot and the `base`, `content`, `remove-button` and `remove-button__base` parts. Core has no tag, so it is built on the `@charm-ux/core` base element and takes Shoelace's markup and styles: a `base` span with the `tag` and `tag--*` classes around the content slot and, while `removable`, an `<sl-icon-button>` remove button (the `x-lg` icon of the `system` library, `tabindex="-1"`, labelled with the localization module's `remove` term in the tag's own or the document's language). The registering entry registers Velcro's `sl-icon-button` and `sl-icon` too, and, as with Shoelace's declared dependencies, constructing a tag defines Velcro's `sl-icon-button` when that tag is not defined yet (and constructing that defines `sl-icon`), so the class-only entry needs no extra step (an `sl-icon-button` another constructor owns is left in place, without Shoelace's version-mismatch warning). Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): the `hidden` attribute does not hide the tag (core's base styles, which would hide it, are replaced by Shoelace's), `variant="text"` is accepted but no rule styles it, a variant or size outside the lists gets no class, the remove button cannot be reached from the keyboard (the tag is not focusable and the button has `tabindex="-1"`), the tag never removes itself, and the remove button is drawn in the icon button's own color until the tag is pressed. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). The docs page has all four of Shoelace's examples in Shoelace's order (Default, Sizes, Pill and Removable), each live with a React version. Not implemented or unverified: the dark theme, right-to-left text, color contrast, and assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM). Registration is browser-only. Adds the `@charm-ux/velcro/tag` and `@charm-ux/velcro/tag/class` exports, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure and styles.
