'@charm-ux/velcro': minor
---

Add a prototype `VelcroIcon`, registered as `sl-icon` on top of the `@charm-ux/core` icon, with Shoelace 2.20.1's API: `name`, `src`, `label` and `library` (`name` and `library` reflect), `sl-load` / `sl-error`, and the `svg` and `use` parts. Icons resolve through registered icon libraries (`registerIconLibrary`, `unregisterIconLibrary`, with resolvers, mutators and sprite sheets) or `src`, share one request cache with Shoelace's cacheable and retryable errors, and set `role="img"` / `aria-label` or `aria-hidden` on the host from `label`. The `default` library is Bootstrap Icons 1.11.3: the package ships all 2,050 icons, their MIT license and an `icons.json` index in `dist/assets/icons` (the build generates the icon files from the release's sprite and checks each against the release's hashes), resolved against the base path (`getBasePath` / `setBasePath`; a `data-shoelace` script attribute wins as in Shoelace, otherwise Velcro uses its own `dist` directory, where Shoelace uses a `shoelace.js` script or the site root). The `system` library is Shoelace's hard-coded data-URI set. Velcro extensions kept from core: the `url` attribute (used like `src` when `src` is not set) and the `icon-load` / `icon-error` events, fired together with `sl-load` / `sl-error`. Not used from core: its icon set, fallback icon, visually hidden label, `icon-base` part and styles. All 14 of Shoelace's icon tests pass against Velcro; the 15th is skipped by Shoelace itself. Not implemented or unverified: `utilities/icon-library` and `utilities/base-path` entry points (the functions are exported from the package root and the `icon` entries instead), visual parity beyond computed-style checks in Chromium, other browsers and SSR. Adds the `@charm-ux/velcro/icon` and `@charm-ux/velcro/icon/class` exports (with the `SlIcon` alias) and updates the third-party notices for Bootstrap Icons (MIT) and adapted Shoelace (MIT) code, wording and styles.
