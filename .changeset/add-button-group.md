'@charm-ux/velcro': minor

Add a prototype `VelcroButtonGroup`, registered as `sl-button-group` and built on the `@charm-ux/core` button group, with Shoelace 2.20.1's API (`label`, the public but undocumented `defaultSlot` and `disableRole` members, the default slot and the `base` part), markup and styles, and its behavior including its quirks (listed on the docs page under "Upstream quirks matched"): only the first `sl-button` (or `sl-radio-button`) inside each slotted element gets the `data-sl-button-group__button` position, hover and focus attributes that the button's styles read, they are recomputed only on a slot change and never cleared when a button leaves the group, `aria-label` is always written (empty without a label) and `hidden` does not hide the group. Shoelace's own button group tests run against it and all pass. Core's group styles, its `button-group-button-position`, `vertical` and `split` attributes written to the buttons, its tooltip distance, its `button-group-base` part and its `--button-group-*` custom properties do not apply: the core `vertical` and `split` attributes are accepted but have no effect. Velcro extensions kept from core and labelled as such: `select` (`single` or `multiple`, toggle buttons) and `toolbar` (`role="toolbar"`, a roving tab index and arrow-key focus movement, also in nested groups); they only act when set, and, as in core, only take effect on the next slot change when set after the buttons are slotted. The core `ready` event is kept and labelled as a Velcro extension, and the group's `change` is not emitted. A `toolbar` group keeps its arrow keys when it is disconnected and reconnected (core drops them). `lang` and `dir` are declared as Shoelace's base element declares them: at runtime they are plain reactive properties, and the `dir` setter accepts any string, but its read type, and the manifest, React and JSX types generated from it, stay core's `'ltr' | 'rtl' | 'auto'` (narrower than Shoelace's `string`; fixing it needs a core change). Not implemented or unverified: `sl-dropdown`, `sl-menu` and `sl-tooltip`, so the dropdown, split-button, tooltip and toolbar docs examples use plain `span` stand-ins (no menu opens and the tooltips are `title` attributes), `sl-radio-button` (the group already looks for it), checks with assistive technology beyond Shoelace's own axe test, RTL and a dark theme, and the product tests were run in Chromium and WebKit only (Firefox runs in CI). Registration is browser-only. Adds the `@charm-ux/velcro/button-group` and `@charm-ux/velcro/button-group/class` exports (with the `SlButtonGroup` alias), the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, behavior and styles.
