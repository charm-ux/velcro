Add a prototype `VelcroQrCode` (alias `SlQrCode`), registered as `sl-qr-code` and built on the `@charm-ux/core` base element (there is no core QR code), with Shoelace 2.20.1's API: the `value`, `label`, `size`, `fill`, `background`, `radius` and `error-correction` properties (none reflected; defaults `''`, `''`, 128, black, white, 0 and H), the public `canvas` field and `generate()` method, and the `base` part, a `<canvas>` with `role="img"` whose accessible name is the label, or else the value. The code is drawn by `qr-creator` 1.0.0, the package and version Shoelace uses, with Shoelace's options (at twice the size, displayed at `size` CSS pixels); it is a new runtime dependency of `@charm-ux/velcro`, pinned exactly, with no transitive dependencies. The product tests compare every drawn canvas byte for byte with qr-creator's drawing from Shoelace's options and pin the module pattern of the docs examples' code at each error correction level. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): each changed drawing property draws the code once more in the same update, the inline canvas makes a standards-mode host a few pixels taller than `size`, a non-numeric or removed `size` leaves a 0 by 0 bitmap, removing an attribute does not restore its default (a removed `value` leaves an empty `aria-label`), the bitmap is twice `size` whatever the pixel ratio, the `hidden` attribute does not hide it, an unparsable `fill` leaves a blank square, and there is no quiet zone. Shoelace's own QR code tests run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` read type stays core's `'ltr' | 'rtl' | 'auto'`). Shoelace's five docs examples and their React versions are ported (the React ones import Velcro's generated wrappers; nothing else differs). Not implemented or unverified: the dark theme, a QR scanner app, and assistive technology (the accessibility-tree check is Playwright's ARIA snapshot); Firefox runs in CI only. Registration is browser-only. Adds the `@charm-ux/velcro/qr-code` and `@charm-ux/velcro/qr-code/class` exports, the vendored Shoelace test file to the conformance suite, and the third-party notices for adapted Shoelace (MIT) code and the `qr-creator` (MIT) dependency.
