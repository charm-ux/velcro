Add prototype `VelcroColorPicker` (alias `SlColorPicker`), registered as `sl-color-picker` and built on the `@charm-ux/core` base element (core has no color picker), with Shoelace 2.20.1's API: the `value`, `label`, `format` (`hex`, `rgb`, `hsl` or `hsv`), `swatches` (a semicolon-separated string or an array), `opacity`, `uppercase`, `no-format-toggle`, `hoist` and `name` attributes, the reflected `inline`, `size`, `disabled`, `form` and `required` (restored to their initial value when set to null or undefined, as Shoelace's base element does), `defaultValue` (tracking the `value` attribute), the `validity` and `validationMessage` getters, the `focus()`, `blur()`, `getFormattedValue()`, `checkValidity()`, `getForm()`, `reportValidity()` and `setCustomValidity()` methods, the `sl-blur`, `sl-change`, `sl-focus`, `sl-input` and `sl-invalid` events, the `label` slot, Shoelace's 26 parts and the `--grid-width`, `--grid-height`, `--grid-handle-size`, `--slider-height`, `--slider-handle-size` and `--swatch-size` custom properties. Shoelace's markup and styles are used unchanged: the dropdown and inline layouts, the color grid and the hue and opacity sliders (pointer dragging through Velcro's shared drag helper, and the arrow keys by 1, by 10 with Shift, Home and End), the swatches, the text input, the format toggle, the copy-on-preview button, the eye dropper (only where the browser has the `EyeDropper` API) and form participation (submitted value, reset, `required` and custom validity). Labels use Velcro's translation terms (`lang`). Constructing a color picker defines Velcro's `sl-button-group`, `sl-button`, `sl-dropdown`, `sl-icon`, `sl-input` and `sl-visually-hidden` when those tags are not defined yet (the dependencies are also registered by the entry), so the class-only entry needs no extra step. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): Enter on a swatch applies it without emitting `sl-change` or `sl-input`; without `opacity`, a value with alpha is rewritten without it but still drawn transparent; a value that cannot be parsed is kept as the value while the input shows the previous color; changing `inline` after the first render makes that update throw a `TypeError`; the format toggle re-reads the rounded value, so a full cycle can drift (`#4a90e2` comes back as `#4b92e3`); and in the dropdown the panel's `aria-labelledby` names no element. Colors are parsed and formatted through one internal adapter (`internal/color.ts`) that exposes only the TinyColor calls Shoelace makes; Shoelace uses `@ctrl/tinycolor`, and whether Velcro takes that dependency or ships its own copy is not decided yet, so the adapter is an interim implementation of the same rules in which CSS color names are resolved by the browser's canvas parser (a name the browser knows but TinyColor does not, such as a CSS system color, is accepted). Shoelace's own color picker tests (52, one of them skipped upstream) run against it, and the other 51 pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/color-picker-dir.tsx`). Shoelace's seven color picker examples (HTML and React) are ported and live; the React examples differ from Shoelace's only in their imports. Not implemented or unverified: the dark theme and color contrast, assistive technology (the accessibility attributes are checked in the DOM), the eye dropper itself (it needs a real user gesture), the copied clipboard contents, a real touch device (touch is checked with synthetic events), and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/color-picker` and `@charm-ux/velcro/color-picker/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite (the conformance gate now binds an upstream `it.skip` by its exact title also when the vendored file runs shared helper tests its scan cannot see), and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
