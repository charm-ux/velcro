Add `<sl-copy-button>`, with Shoelace 2.20.1's copy button contract (exports `./copy-button` and `./copy-button/class`): `value`, `from`, `disabled`, `copy-label`, `success-label`, `error-label`, `feedback-duration`, `tooltip-placement` and `hoist`; the `sl-copy` and `sl-error` events; the `copy-icon`, `success-icon` and `error-icon` slots; the `button`, `copy-icon`, `success-icon`, `error-icon` and `tooltip__*` parts; the `--success-color` and `--error-color` custom properties; and the `copy.in` / `copy.out` animations from the animation registry. The default labels use the localization module's `copy`, `copied` and `error` terms. The copy button renders Velcro's `<sl-tooltip>` and `<sl-icon>`; constructing one defines them when the tags are free (and the tooltip defines `<sl-popup>`), with Shoelace's version-mismatch warning when another constructor of a different version owns a tag. Shoelace's quirks are matched and listed on the docs page (for example, a `from` that names no element reports an error and then still copies `value`, and `hidden` does not hide the button). The `dir` read type stays core's `'ltr' | 'rtl' | 'auto'` (the setter accepts any string). The only core extension kept is the non-bubbling `ready` event. Adds the third-party notice for the adapted Shoelace (MIT) code.

Fix `<sl-tooltip>`'s show and hide animations to choose the `rtlKeyframes` variant from the localization controller's document-direction snapshot, as Shoelace's does, instead of reading `<html dir>` live; a change made in the same task as `show()` or `hide()` is therefore not seen by that animation, as in Shoelace.

The docs examples that Shoelace wraps in `<sl-tooltip>` now use the live element: the icon button's Icon Button with Tooltip example gains a live preview and a React version, the button group's tooltip and toolbar examples wrap their buttons in `<sl-tooltip>`, and the icon search shows each icon's name in a tooltip.
