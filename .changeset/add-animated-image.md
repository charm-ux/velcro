Add prototype `VelcroAnimatedImage` (alias `SlAnimatedImage`), registered as `sl-animated-image` and built on the `@charm-ux/core` base element (core has no animated image), with Shoelace 2.20.1's API: the non-reflected `src` and `alt`, the reflected `play` (all three undefined until set), the public `animatedImage`, `frozenFrame` and `isLoaded` fields and the `handlePlayChange` and `handleSrcChange` watch handlers, the `sl-load` and `sl-error` events, the `play-icon` and `pause-icon` slots (default system `play-fill` and `pause-fill` `sl-icon`s), the `control-box` part and the `--control-box-size` and `--icon-size` custom properties. Shoelace's markup and styles are used unchanged: an animated `img` (requested with `crossorigin="anonymous"`) and, once it has loaded, a frozen first frame drawn on a canvas and a control box; a click on either image toggles `play`; playing reloads the image so the animation restarts. Constructing an animated image defines Velcro's `sl-icon` when that tag is not defined yet (the dependency is also registered by the entry), so the class-only entry needs no extra step. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): an animated image without a `src`, or with it removed, renders an empty `src` and reports `sl-error` in Chromium and WebKit; the two default icons' own `sl-load` events bubble out, so a listener on the host sees three `sl-load` events per source; the frozen frame is always the first frame (browsers draw the first frame of an animated image on a canvas); `play` is undefined rather than false until set and setting it to null or undefined leaves it so; the element is not focusable and has no keyboard operation or role; an animated image without `alt` renders `alt=""` on both images; the image is always requested with CORS, so a cross-origin source without CORS headers fails; the `hidden` attribute does not hide it; and the images follow the host's height and only shrink to its width. Shoelace's own animated image tests (9) run against it and all pass. The core `ready` event is kept and labelled as a Velcro extension; `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; its read type stays core's `'ltr' | 'rtl' | 'auto'`, checked in `type-tests/animated-image-dir.tsx`). Shoelace's four animated image examples (HTML and React) are ported and live, with two small synthetic images written for Velcro (a GIF and a WEBP, inline as data URLs) in place of Shoelace's demo images, which need network access; the upstream test runner serves the same two images, stored as base64 text because binary files are not committed, at the `docs/assets/images/walk.gif` and `tie.webp` paths Shoelace's test requests. Not implemented or unverified: the dark theme, assistive technology (the accessibility-tree check is Playwright's ARIA snapshot, computed from the DOM) and Firefox locally (CI runs it). Registration is browser-only. Adds the `@charm-ux/velcro/animated-image` and `@charm-ux/velcro/animated-image/class` exports, the React wrapper, the vendored Shoelace test file to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
