Add a prototype `VelcroTextarea` (alias `SlTextarea`), registered as `sl-textarea` on top of the `@charm-ux/core` text area (core's class is named `text-area`; the tag follows Shoelace), with Shoelace 2.20.1's API: the `name`, `value`, `defaultValue`, `size`, `filled`, `label`, `help-text`, `placeholder`, `rows`, `resize` (`none`, `vertical`, `auto`), `disabled`, `readonly`, `form`, `required`, `minlength`, `maxlength`, `autocapitalize`, `autocorrect`, `autocomplete`, `autofocus`, `enterkeyhint`, `spellcheck` and `inputmode` properties (with Shoelace's defaults and reflection: `size`, `filled`, `disabled`, `readonly`, `form` and `required` reflect, and removing a reflected attribute restores its initial value), the `focus()`, `blur()`, `select()`, `scrollPosition()`, `setSelectionRange()`, `setRangeText()`, `checkValidity()`, `reportValidity()`, `setCustomValidity()` and `getForm()` methods, the `validity` and `validationMessage` getters, the `sl-blur`, `sl-change`, `sl-focus`, `sl-input` and `sl-invalid` events, the `label` and `help-text` slots, the `form-control`, `form-control-label`, `form-control-input`, `form-control-help-text`, `base` and `textarea` parts, Shoelace's markup, styles and tokens, auto-resizing, and its form participation (the `formdata`, `submit` and `reset` handling, the `data-valid` / `data-invalid` / `data-user-valid` / `data-user-invalid` / `data-required` / `data-optional` attributes, and the replaced `checkValidity()` and `reportValidity()` of the form). Like Shoelace's, the element is not form-associated, does not delegate focus and has the `hidden` quirk. Shoelace's behavior is matched including its quirks (listed on the docs page under "Upstream quirks matched"): the `hidden` attribute does not hide the textarea, `scrollPosition()` reads `left` as the vertical offset, `form=""` is always reflected, `aria-describedby` always points at the help text, removing the `value` attribute sets `value` and `defaultValue` to `null`, and the methods throw before the first render. Shoelace's own textarea test file (43 tests, including its axe check) runs against it and passes. Shoelace's `serialize()` and `getFormControls()` are added as `@charm-ux/velcro/utilities/form` (also exported from the package root and the `textarea/class` entry, as Shoelace's package root does). The core `change` and `input` events are not emitted (Shoelace's `sl-change` and `sl-input` are) and core's keydown handling, styles, parts, markup and `--form-control-*` properties do not apply. Velcro extensions kept from core and labelled as such in the API reference and types: `hide-label` and `error-message`; the core `invalid` and `label-position` properties are accepted and reflected but have no effect, the host carries core's `focusable` attribute and the core `ready` event is kept. `dir` and `lang` are declared as Shoelace's base element declares them (the `dir` setter accepts any string; the read type stays core's `'ltr' | 'rtl' | 'auto'`). Type gap: `resize`, `autocomplete` and `autocorrect` are typed `any` in the source and declarations because TypeScript does not let the subclass narrow the inherited property types, while the manifest carries Shoelace's types. Not implemented or unverified: Shoelace's `resize` values are the only styled ones (core's `horizontal` and `both` fall back to the browser default, as in Shoelace), the dark theme, right-to-left text, assistive technology beyond Shoelace's axe test, and the product tests were run in Chromium and WebKit only (Firefox runs in CI). Registration is browser-only. Adds the `@charm-ux/velcro/textarea`, `@charm-ux/velcro/textarea/class` and `@charm-ux/velcro/utilities/form` exports, the React wrapper, the vendored Shoelace test file and form utility to the conformance suite, and updates the third-party notices for adapted Shoelace (MIT) wording, structure, behavior and styles.
