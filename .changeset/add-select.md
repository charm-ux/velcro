Add `<sl-select>` and `<sl-option>`, with Shoelace 2.20.1's select and option contracts (exports `./select`, `./select/class`, `./option` and `./option/class`). The select: `name`, `value` (a string, or an array of strings with `multiple`; the `value` attribute sets `defaultValue`), `size`, `placeholder`, `multiple`, `max-options-visible`, `disabled`, `clearable`, `open`, `hoist`, `filled`, `pill`, `label`, `placement`, `help-text`, `form`, `required` and `getTag`; `show()`, `hide()`, `checkValidity()`, `getForm()`, `reportValidity()`, `setCustomValidity()`, `focus()` and `blur()`; the `sl-change`, `sl-clear`, `sl-input`, `sl-focus`, `sl-blur`, `sl-show`, `sl-after-show`, `sl-hide`, `sl-after-hide` and `sl-invalid` events; Shoelace's slots and parts; the keyboard, pointer and type to select behavior; form data and validation through the closest or named `<form>`; and the `select.show` / `select.hide` animations from the animation registry. The option: `value`, `disabled` and `getTextLabel()`, with its label, `prefix` and `suffix` slots and Shoelace's parts. The select is built on the `@charm-ux/core` select with Shoelace's template, styles and behavior; it renders Velcro's `<sl-popup>`, `<sl-tag>` and `<sl-icon>` and defines them when it is constructed and the tags are free, while `<sl-option>` is registered by its own entry, as in Shoelace. Core's `hide-label` and `error-message` keep working; `invalid`, `label-position` and `readonly` are inert. Shoelace's quirks are matched and listed on the docs pages (for example, opening the listbox focuses the highlighted option so the select emits `sl-blur`, `show()` on an open select closes it, and `hidden` does not hide either element). The `dir` read type stays core's `'ltr' | 'rtl' | 'auto'` (the setter accepts any string). Adds the third-party notices for the adapted Shoelace (MIT) code.
